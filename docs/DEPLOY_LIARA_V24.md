# راهنمای استقرار آزمایشی v24 روی Liara

## اقدامات پیش از انتشار

۱. از دیتابیس و تنظیمات پروژه فعلی backup بگیرید. استقرار آزمایشی را در یک app/test environment جدا آغاز کنید.  
۲. مخزن GitHub یا ZIP v24 را به پروژه Docker بدهید؛ `Dockerfile` در ریشه و `frontend/` کنار `backend/` قرار دارد.  
۳. متغیرهای اجباری Liara: `ADMIN_PASSWORD`، `SESSION_SECRET` با حداقل ۳۲ نویسه، `DB_PATH` با مسیر mount پایدار؛ `PORT` توسط Liara یا متغیر پیش‌فرض ۸۰۰۰. `FRONTEND_DIST` در Dockerfile به `/app/frontend/dist` تنظیم شده است.  
۴. برای جست‌وجوی پشتیبان، مقدار واقعی `AVALAI_API_KEY` را در Secret/Environment مخصوص Liara قرار دهید؛ در GitHub ثبت نکنید. APIهای اختیاری دیگر تنها پس از گرفتن مجوز رسمی فعال شوند.  
۵. در ابتدا تنها **یک replica** اجرا کنید؛ دیتابیس SQLite و job executor فعلاً برای چند replica قابل اتکا نیستند.

## بررسی بعد از استقرار

```bash
curl https://YOUR-APP.liara.run/api/health
```

خروجی باید نسخه `24.0.0-release-candidate` داشته باشد. صفحه اصلی باید **React** را نشان دهد نه پاسخ 503. وارد شوید، خروج و ابطال نشست را بررسی کنید، یک استعلام با داده کامل اجرا کنید، خطای 422 برای داده ناقص را ببینید، وضعیت منابع و لینک‌ها را بررسی کنید.

## سناریوهای پیشنهادی

- «فیدلیتی پرایم مدل ۱۴۰۳ کارکرد ۵۰ هزار بدون رنگ اتوماتیک»
- «سانتافه ۲۰۲۵ صفر کیلومتر اتوماتیک» (در صورت ابهام نسخه/تیپ، مشخصات را تأیید کنید)
- «فیدلیتی پرستیژ مدل ۱۴۰۲ رنگ‌شده ۹۰ هزار کیلومتر»
- صفحه مقاله با قیمت ضمنی/کارمزد، آگهی ۶۵ روزه، سال اشتباه، تیپ مغایر یا لینک خراب

نبودن شواهد معتبر به معنی شکست سامانه نیست، اما باید علت دسترسی/استخراج هر سایت قابل مشاهده باشد. **هیچ قیمت فاقد URL و تاریخ انتشار معتبر نباید برای معامله مبنا شود.**

## معیار Go/No-Go

- GitHub Actions سبز + Docker build موفق
- صفحه React و API روی Liara کار کند
- سه منبع واقعی با داده معتبر (به‌شرط دسترسی مجاز) بررسی شوند
- نرخ خطا، محدودیت زمانی، Restart و حفظ اطلاعات کاربر تأیید شود
- تست دستی Chrome/Safari اندروید/iOS روی ۳۹۰ و ۱۴۴۰ پیکسل
- بکاپ/بازگردانی دیتابیس و تغییر رمزها امتحان شود

**تا انجام موارد بالا، پروژه Release Candidate است، نه تولید نهایی.**
