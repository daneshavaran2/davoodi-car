# Davoodi Car v26 — استخراج آگهی عمومی با Playwright

**وضعیت انتشار:** سورس برای استقرار آزمایشی آماده است؛ استخراج زنده از سایت‌های ثالث در این محیط تأیید نشده و نباید به‌عنوان «بدون خطا» یا «داده کامل» معرفی شود.

## مسئله نسخه ۲۵

- کانکتورهای داخلی، HTML اولیه را با urllib می‌خواندند؛ کارت‌هایی که بعد از JavaScript ساخته می‌شوند ممکن بود حذف شوند.
- متن لینک به‌جای **کل کارت آگهی** خوانده می‌شد؛ قیمت و کارکردی که کنار لینک قرار دارند دیده نمی‌شدند.
- اگر چند آگهی در یک صفحه باشد، برداشتن قیمت از کل صفحه می‌تواند قیمت خودرو دیگری یا مبلغ کارمزد را به خودرو فعلی نسبت دهد.
- اگر سایت HTTP 403/429 یا صفحه کپچا بدهد، نباید آن را معادل «هیچ آگهی وجود ندارد» دانست.

## پیاده‌سازی

1. `backend/connectors/browser.py`: اجرای Chromium با Playwright؛ مرورگر اختصاصی هر worker/منبع، مسدودکردن تصویر، فونت و ویدئو برای سرعت، سقف زمان و محدودیت هم‌زمانی، HTTPS و دامنه مجاز. **هیچ مکانیزم دورزدن کپچا، محدودیت دسترسی، ورود یا اثرانگشت مرورگر وجود ندارد.**
2. `backend/connectors/extract.py`: پردازش DOM رندرشده با BeautifulSoup؛ یافتن کارت‌های جداگانه، متن و قیمت هر کارت، اسناد JSON-LD در جزئیات، تاریخ واقعی آگهی اگر موجود باشد. اطلاعات نامشخص، نامشخص باقی می‌مانند.
3. `backend/connectors/bama.py`, `hamrah.py`, `divar.py`: کانکتورهای عمومی مبتنی بر صفحه‌های جست‌وجو و جزئیات.
4. `backend/connectors/khodro45.py`: برای **قیمت مرجع** (نه لزوماً آگهی فروش). مرجع در موتور امتیاز اعتبار ضریب متفاوت دارد؛ صفحه خبر/مقاله حذف می‌شود.
5. `backend/connectors/common.py`: استخراج امن قیمت و کارکرد را با `safety_v24.py` یکسان می‌کند.
6. اجرای Chromium در Docker با ایمیج رسمی `mcr.microsoft.com/playwright/python:v1.57.0-noble` و نسخه Python Playwright یکسان. خروجی React نیز در build بررسی می‌شود.

## محدودیت‌های منابع

| منبع | روش فعلی | تأیید زنده |
| --- | --- | --- |
| باما | صفحه فهرست + جزئیات با Playwright | خیر |
| دیوار | جست‌وجوی عمومی شهر/مدل + جزئیات با Playwright | خیر |
| همراه مکانیک | فهرست + جزئیات با Playwright | خیر |
| خودرو۴۵ | استخراج قیمت مرجع (متفاوت با آگهی فروش) | خیر |
| کارنامه، شیپور | کانکتور خارجی مجاز (`*_CONNECTOR_URL`) یا جست‌وجوی تکمیلی دارای کلید | خیر |

ساختار URL و دسترسی سایت‌ها ممکن است تغییر کند؛ در این حالت امکان عدم استخراج وجود دارد. برای پوشش کامل و پایدار، API یا دسترسی رسمی/قراردادی از هر منبع موردنیاز است. Playwright جایگزین مجوز استفاده از داده‌ها نمی‌شود.

## پیکربندی Liara

- `MARKET_FETCH_MODE=playwright` — پیش‌فرض: مرورگر واقعی برای صفحات پویا.
- `MAX_CONCURRENT_BROWSERS=2` — سقف Chromiumهای هم‌زمان در هر پردازش؛ برای سرور کم‌حافظه به `1` کاهش یابد.
- `MAX_DETAIL_PAGES_PER_SOURCE=6` — سقف خواندن جزئیات برای هر منبع در یک استعلام.
- `MARKET_FETCH_MODE=auto` — HTML سریع؛ در صورت صفحه صرفاً JS به مرورگر ارتقا می‌دهد.
- `MARKET_FETCH_MODE=http` — حالت پشتیبان بدون مرورگر. فقط HTML اولیه را استخراج می‌کند.
- `ADMIN_PASSWORD`, `SESSION_SECRET`, `DB_PATH` و در صورت نیاز `AVALAI_API_KEY` باید در Liara تنظیم شوند؛ رمزها را commit نکنید.
- اگر حجم رم سرور کمتر از حد لازم برای ۱–۲ مرورگر باشد، کانکتور خطای واقعی ظرفیت را می‌دهد؛ پلن Liara را ارتقا دهید یا ظرفیت مرورگر را کاهش دهید.
- مسیر `/api/readiness` فیلد `market_fetch_mode` و نام چهار منبع دارای کانکتور مرورگر را برمی‌گرداند. **این فیلد، موفقیت استخراج زنده را ثابت نمی‌کند.**

## اجرای محلی و تست

```bash
cd backend
python -m pip install -r requirements-test.txt
python -m playwright install chromium
python test_v21_market_fix.py
python test_v22_intelligence.py
python test_v23_quality.py
python test_v24_safety.py
BROWSER_TEST_REQUIRED=1 python test_v26_playwright.py
```

در Windows مقداردهی `BROWSER_TEST_REQUIRED` را به شکل مناسب PowerShell انجام دهید. در CI تست واقعی Chromium با تصویر/DOM ساختگی انجام می‌شود تا وابسته به وضعیت و محدودیت سایت‌های شخص ثالث نباشد.
