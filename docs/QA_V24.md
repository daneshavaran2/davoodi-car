# گزارش QA داودی کار نسخه ۲۴

**زمان اجرا:** ۱۲ نوامبر ۲۰۲۶، **محدوده:** سورس فعلی Release Candidate. تست‌ها از داده‌های ساختگی/ثابت استفاده می‌کنند و گواه صحت قیمت بازار نیستند.

## سناریوهای رگرسیون حساس

- «قیمت خودرو ۵ میلیارد تومان، کارمزد ۳۰۰ میلیون» → ۵ میلیارد تومان.
- «پیش‌پرداخت ۳۰۰ میلیون» → قیمت نهایی نامعلوم؛ از ارائه عدد جلوگیری می‌شود.
- «فیدلیتی مدل ۱۴۰۳ کارکرد ۵۰ هزار» → سال ۱۴۰۳ و کارکرد ۵۰٬۰۰۰.
- «تحویل فوری» کنار کارکرد مثبت → صفر کیلومتر طبقه‌بندی نمی‌شود.
- پرایم در برابر پرستیژ → شواهد متضاد از برآورد کنار گذاشته می‌شوند.
- آگهی بدون تاریخ انتشار واقعی → در بخش «نیازمند بررسی» نه قیمت قابل اتکا.
- درخواست بدون تیپ فیدلیتی/سال/کارکرد/وضعیت بدنه کارکرده → 422 و بدون درخواست هزینه‌دار.
- ۵ بار رمز اشتباه → پاسخ محدودیت 429؛ logout → نشست قبلی 401.
- جست‌وجوی هم‌زمان → job_id و progress واقعی؛ نشست دیگری به وظیفه دسترسی ندارد.

## انجام‌نشده یا ناموفق در محیط فعلی

| آزمون | نتیجه | دلیل/اقدام لازم |
|---|---|---|
| نصب کامل npm / build Vite | تأیید نشده | شبکه دسترسی به بسته‌های نصب‌نشده نداشت؛ در GitHub Actions اجرا شود |
| ساخت Docker واقعی | تأیید نشده | Docker در محیط ساخت موجود نبود؛ تست در CI یا Liara |
| React + API در Chromium | تأیید نشده | سرور loopback در مرورگر این محیط به دلیل policy مسدود شد؛ با staging واقعی آزمایش شود |
| دقت زنده قیمت دیوار/باما/… | تأیید نشده | بدون مجوز/کلید واقعی و شواهد قابل بررسی زنده |
| تست iOS Safari/Android Chrome واقعی | تأیید نشده | آزمایش دستی روی staging الزامی |
| GitHub Actions سبز | در لحظه ساخت تأیید نشده | خطاهای قبلی حتی پیش از شروع step رخ می‌دادند؛ وضعیت Runner/سهمیه/تنظیمات را بررسی کنید |
| تست فشار چند replica | انجام نشده | معماری فعلی محدود به single instance |

## خطاهای باقیمانده شناخته‌شده / ریسک عملیاتی

- با سختگیری تاریخ آگهی و تیپ، ممکن است سامانه به‌جای قیمت، «داده کافی نیست» نشان دهد؛ قیمت حدسی نباید جایگزین شود.
- استخراج HTML سایت‌های JS-based ممکن است به نتیجه معتبر نرسد؛ fallback در صورت داشتن API key عمل می‌کند و تضمین ندارد.
- worker درون پردازش پس از restart job را از سر نمی‌گیرد.
- پایگاه داده SQLite در چند replica امن نیست؛ استفاده از فقط یک replica توصیه می‌شود.
- مدیریت کاربران و نقش‌ها فقط با رمز مشترک مدیریت انجام می‌شود، نه کاربران اختصاصی.
- نبود راهکار مانیتورینگ واقعی uptime و log مرکزی؛ قبل از تولید باید اضافه شود.
