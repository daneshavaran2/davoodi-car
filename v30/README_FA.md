# رفع خطای ۵۰۲ — نسخه ۳۰.۱

[راهنمای رفع HTTP 502 روی Liara](docs/HTTP502_LIARA_FA.md) — وب‌سرور حتی هنگام قطعی PostgreSQL اجرا می‌شود و API وضعیت را به‌صورت JSON گزارش می‌کند. تا مشاهده لاگ واقعی Liara، علت نهایی خطا قطعی نیست.

# داودی‌کار — نسخه ۳۰، معماری جست‌وجوی فوری قیمت از بانک اطلاعاتی

**وضعیت تحویل: نسخه توسعه‌ای قابل استقرار پس از تنظیم دیتابیس و منابع دارای مجوز؛ نه نسخهٔ تأییدشدهٔ عملیاتی روی Liara.**

در این نسخه، رابط فارسی React، API با FastAPI، بانک PostgreSQL، ورود ۶۶۰ خودرو از کاتالوگ کارفرما، استخراج/اعتبارسنجی مستقل در Worker، محاسبهٔ بازهٔ قیمت و زمان‌بند ساعتی پیاده‌سازی شده‌اند. **هیچ قیمت واقعی در دادهٔ اولیه موجود نیست.** آگهی و قیمت بدون اتصال *واقعاً تأییدشده* به فید مجاز وارد DB نمی‌شود. شش سایت فعلاً در DB **غیرفعال** ایجاد می‌شوند و تنها پس از فعال‌سازی آگاهانهٔ مدیر و تنظیم آدرس اتصال مجاز می‌توانند دریافت را شروع کنند. 

## اصل طراحی

```
React (یک کادر جست‌وجو)
     ↓ فقط GET از PostgreSQL
FastAPI ── PostgreSQL (کاتالوگ، آگهی، قیمت‌های تاریخ‌دار)
                ↑
         Worker مستقل، هر ساعت
                ↑
        API/فید مجاز منابع
```

**هیچ اجرای Playwright یا درخواست HTTP به سایت‌های آگهی داخل API جست‌وجوی کاربر وجود ندارد.** استفاده از Playwright برای منابع JS، در صورت مجوز و آزمایش واقعی، باید به‌صورت آداپتر مستقل Worker به این ساختار اضافه شود؛ این نسخه مرورگر اجباری ندارد. این تصمیم خطاهای قبلی Liara در Pull مرورگر و تأخیر پردازش درخواست را کاهش می‌دهد، ولی معادل پوشش خودکار همه سایت‌ها نیست.

## نصب محلی با Docker Compose

۱. فایل `.env.example` را به `.env` کپی کنید و حتماً `POSTGRES_PASSWORD` و `ADMIN_TOKEN` را با رمزهای قوی اختصاصی جایگزین کنید. در Docker Compose مقدار `DATABASE_URL` توسط Compose از پسورد ساخته می‌شود؛ PostgreSQL در شبکه داخلی است.

۲. اجرا:

```bash
docker compose up --build -d
```

سه سرویس ایجاد می‌شوند: `postgres`، `web` و `worker`، که هر دو برنامه از PostgreSQL مشترک استفاده می‌کنند. Web و Worker هنگام بوت Migration و import کاتالوگ را تحت advisory lock انجام می‌دهند. URL وب: `http://localhost:8000`.

۳. آزمون:

```bash
curl http://localhost:8000/api/v1/health
curl 'http://localhost:8000/api/v1/vehicles/search?q=%D9%81%DB%8C%D8%AF%D9%84%DB%8C%D8%AA%DB%8C'
curl 'http://localhost:8000/api/v1/prices/estimate?q=%D8%B3%D8%A7%D9%86%D8%AA%D8%A7%D9%81%D9%87%20%DB%B2%DB%B0%DB%B1%DB%B7'
```

قبل از فعال‌سازی منابع، جست‌وجوی قیمت باید `no_data` بدهد، نه عدد خیالی. این رفتار صحیح است.

## انتشار روی Liara

به **یک PostgreSQL پایدار** و **دو برنامه Docker مجزا** نیاز است که کد یکسان، اما نقش متفاوت دارند:

- **وب:** پلتفرم Docker، دامنه `davoodicar.liara.run`، `SERVICE_ROLE=web`، مقدارهای `DATABASE_URL` و `ADMIN_TOKEN`؛ فرمان پیش‌فرض Dockerfile FastAPI را اجرا می‌کند.
- **Worker:** برنامه Docker دوم بدون دامنه عمومی، `SERVICE_ROLE=worker` و همان `DATABASE_URL` و `ADMIN_TOKEN`؛ اتصال‌های `SOURCE_..._API_URL` و `SOURCE_..._API_TOKEN` فقط اینجا لازم‌اند.
- هر دو نقش یک فایل Dockerfile دارند؛ bootstrap کاتالوگ و migration روی شروع هر دو، با lock اختصاصی اجرا می‌شود.
- زمان‌بند مستقل در Worker رأس هر ساعت طبق `SCHEDULER_TZ=Asia/Tehran` اجرا می‌شود. در نصب اولیه Worker یک اجرای ساعتی انجام می‌دهد. برای راه‌اندازی cron بیرونی نیز می‌توان از `python -m backend.worker --once` استفاده کرد؛ از اجرای همزمان دو Worker اجتناب کنید.
- در صورت نبود پشتیبانی پلن Liara از Worker مستقل، باید cron job مستقل اجرا شود. بازبودن صفحه مرورگر هیچ نقشی در زمان‌بندی ندارد.
- به‌دلیل محدودیت دسترسی به حساب Liara در این محیط، **این تنظیمات روی اپ واقعی ایجاد یا تست نشده‌اند**. پیش از تغییر دامنه اصلی، ابتدا روی یک دامنه آزمایشی نصب و با معیارهای پایین تأیید کنید.

**مهم:** روی یک URL/کانتینر واحد فقط `web` یا `worker` اجرا می‌شود. `SERVICE_ROLE=web` به‌تنهایی هیچ جمع‌آوری ساعتی ندارد. Dockerfile عمداً روی خطای نصب frontend متوقف می‌شود.

## وصل کردن منابع مجاز

برای هر سایت، یک endpoint HTTPS **تحت کنترل شما یا دارنده مجوز رسمی** فراهم کنید. نام‌های کانفیگ: `SOURCE_DIVAR_API_URL`، `SOURCE_BAMA_API_URL`، `SOURCE_SHEYPOOR_API_URL`، `SOURCE_HAMRAH_API_URL`، `SOURCE_KARNAMEH_API_URL` و `SOURCE_KHODRO45_API_URL`. توکن هر کدام با پسوند `_API_TOKEN` در Secrets.

- هیچ آدرس endpoint فعالی در ZIP نیست، چون از این محیط اتصال مجاز هر سایت اثبات نشده است.
- پس از تأیید حقوق دسترسی، مدیر با پنل «مدیریت منابع» منبع را فعال می‌کند.
- Worker یک درخواست POST با `{"catalog_version":"v30","locale":"fa-IR","cursor":null,"page_size":100}` به endpoint می‌فرستد. پاسخ باید شکل `{"items":[...],"next_cursor":null}` باشد.
- هر item باید شامل فیلدهای `url` (HTTPS دامنه رسمی)، `external_id`، `title`، `brand`، `model`، `trim`، `model_year`، `condition` (`new`/`used`)، `mileage_km`، `transmission` (`automatic`/`manual`)، `body_condition`، `price_toman` (عدد صحیح **تومان**) یا `price` و `currency` معتبر، `raw_type:"listing"`، `published_at` (ISO timezone-aware، فقط در صورت وجود واقعی) و `city` باشد.
- مثال *صرفاً شکل داده*، با مقدار قیمت **آزمایشی** برای تست واحد؛ **به‌عنوان آگهی واقعی وارد Production نکنید**:

```json
{"items":[{"url":"https://bama.ir/car/detail-EXAMPLE-NOT-REAL", "external_id":"EXAMPLE", "title":"فیدلیتی پرایم مدل ۱۴۰۳", "brand":"بهمن", "model":"فیدلیتی پرایم", "trim":"پرایم", "model_year":1403, "condition":"used", "mileage_km":55000, "transmission":"automatic", "body_condition":"original", "raw_type":"listing", "price_toman":2500000000,"currency":"toman", "city":"تهران"}],"next_cursor":null}
```

Worker آگهی‌هایی با مدل/سال/تیپ ناسازگار، وضعیت متناقض، قیمت نامشخص یا ناقص، تعداد ناکافی و URL غیراصلی را به قیمت نهایی راه نمی‌دهد. برای هر منبع timeout، محدودیت صفحه، نرخ دریافت و ثبت کد شکست اعمال می‌شود. **برای سرویس‌های محدود، از CAPTCHA/لاگین یا موانع ضدربات عبور نکنید.**

## محاسبه و تازگی

- تنها آگهی فروش قیمت‌دار (`raw_type=listing`) با سال مدل واقعی منبع قابل استفاده است. سال تقریبی CSV جایگزین آن نمی‌شود.
- قیمت به **تومان صحیح** ثبت می‌شود؛ تبدیل ریال فقط با فیلد واحد صریح انجام می‌شود.
- مجموعه‌های هم‌سال، هم‌مدل، هم‌تیپ، هم‌گیربکس، هم‌وضعیت بدنه و بازه کارکرد همگن هستند.
- حداقل **۵ آگهی مستقل** برای ایجاد بازه لازم است؛ ۵–۹ آگهی: کم‌اطمینان با بازه کمینه/بیشینه؛ از ۱۰ آگهی: صدک تجربی ۲۰/۸۰ و میانه.
- حداقل ۲ منبع در نمونه ده‌تایی برای سطح اطمینان «بالا» لازم است. سطح اطمینان، **درصد احتمال دقت قیمت نیست**.
- آگهی‌های منقضی بیش از ۱۴ روز از محاسبات بعدی کنار گذاشته می‌شوند؛ timestamp انتشار واقعی هرگز با timestamp مشاهده پر نمی‌شود.
- قیمت محاسبه‌شده تا **۲ ساعت fresh**، ۲ تا ۲۴ ساعت **stale** و بعد از ۲۴ ساعت فقط به‌عنوان سابقه نگه‌داری می‌شود (به کاربر نمایش داده نمی‌شود).
- شکست دریافت یک سایت باعث بازنویسی با صفر نمی‌شود. `fetch_runs` و `scheduler_runs` تاریخچهٔ شکست را حفظ می‌کنند.

## API

| مسیر | دسترسی | عملکرد |
|---|---|---|
| `GET /api/v1/health` | عمومی | بررسی API/PostgreSQL؛ نسخه |
| `GET /api/v1/vehicles/search?q=...` | عمومی | پیشنهاد نام خودرو/رفع ابهام |
| `GET /api/v1/prices/estimate?q=...&year=...&trim=...` | عمومی | تنها نتایج ذخیره‌شده؛ بدون جمع‌آوری زنده |
| `GET /api/v1/sources/status` | مدیر | آخرین تلاش/موفقیت/خطا/آگهی‌های معتبر/زمان‌بند |
| `POST /api/v1/admin/sources/{code}` | مدیر | فعال/غیرفعال کردن منبع با JSON `{"enabled":true}` |
| `POST /api/v1/admin/refresh` | مدیر | ثبت اجرای دستی در صف مستقل Worker |
| `POST /api/v1/admin/vehicles` | مدیر | افزودن مدل و alias جدید |
| `GET /docs` | عمومی | OpenAPI خود FastAPI |

برای مسیرهای مدیر از هدر `Authorization: Bearer <ADMIN_TOKEN>` استفاده کنید. هرگز مقدار توکن را در مخزن یا پیام پشتیبانی قرار ندهید.

## تست

```bash
python -m pip install -r requirements.txt
python -m pip install pytest httpx
python -m pytest -q
python -m compileall -q backend scripts
# Docker build integration when Docker is available:
docker build -t davoodicar:v30 .
```

تست‌های موجود چک می‌کنند که خروجی صفر از کاتالوگ تولید نشود، ۶۶۰ مدل یکتا باشند، اعداد ریال/تومان درست محاسبه شوند، سال/تیپ/بدنه/گیربکس جدا باشند، داده نامعتبر حذف شود، و API در اجرای نمونه‌سازی‌شده به‌سرعت پاسخ دهد.

**هنوز انجام نشده و برای تأیید تولید الزامی است:** اجرای migration روی PostgreSQL واقعی، آزمون endpoints هر منبع با مجوز دسترسی، اجرای مستقل ساعتی ۲۴ ساعت، تست Build Docker روی Liara، اندازه‌گیری p95 در ۱۰۰+ جست‌وجوی واقعی، آزمون بازیابی بکاپ PostgreSQL و کنترل دامنه نهایی. تا تکمیل این موارد برنامه را «Production Verified» ننامید.

## بازگشت به نسخه قدیمی

نسخه ۲۹ React/FastAPI/SQLite موجود را روی دامنه اصلی حذف نکنید تا نسخه ۳۰ در برنامه جداگانه به تأیید برسد. PostgreSQL نسخه ۳۰ مستقل از SQLite نسخه قدیمی است؛ با بازگردانی مسیر دامنه و نسخه Docker قبلی می‌توان rollback کرد، بدون حذف داده‌های نسخهٔ جدید.
