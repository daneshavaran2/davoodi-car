# DavoodiCar v30.5 — انتقال آزمایشی استخراج عمومی v29 به Worker v30

## چه چیزی واقعاً تغییر کرده؟
- parserهای نسخه ۲۹ برای **باما، دیوار و همراه مکانیک** به `backend/legacy_market/` در نسخه ۳۰ منتقل شده‌اند.
- `backend/legacy_bridge.py` خروجی کارت‌ها را به قرارداد محافظه‌کارانه `clean_listing` تبدیل می‌کند.
- استخراج فقط داخل سرویس مستقل Worker انجام می‌شود؛ API کاربر همچنان فقط PostgreSQL می‌خواند.
- سقف پیش‌فرض: **۲ مدل انتخاب‌شده در هر منبع**، هرکدام حداکثر **۸ آگهی**؛ نه پیمایش ۶۶۰ خودرو.
- وضعیت موفق/خطا و تعداد آگهی در همان جداول `fetch_runs` و `data_sources` ثبت می‌شود.
- برخورد با HTTP 403/429/CAPTCHA: **توقف همان منبع، بدون تلاش برای دورزدن**.
- قیمت، سال، تیپ، گیربکس و کارکرد نامعلوم حدس زده نمی‌شود؛ قیمت بدون نشانه تومان رد می‌شود.

## وضعیت منابع
هیچ‌کدام از سه سایت در محیط واقعی Liara در این تحویل **تأیید نشده‌اند**. صرف وجود parser مجوز دسترسی نیست. پیش از فعال‌سازی، شرایط استفاده و مجازبودن دریافت خودکار را با مالک سایت بررسی کنید. برای دیوار API رسمی «کنار دیوار» با دسترسی `SEARCH_POST` وجود دارد؛ در صورت امکان آن را به روش مرورگر عمومی ترجیح دهید. آدرس مستندات:
https://divar-ir.github.io/kenar-docs/

## تنظیمات آزمایش باما پس از تأیید مجازبودن دسترسی

در محیط **فقط Worker**، و فقط پس از بررسی شرایط استفاده باما:

```env
MARKET_FETCH_MODE=playwright
SOURCE_BAMA_MODE=legacy_public
SOURCE_BAMA_PUBLIC_ACCESS_APPROVED=1
PUBLIC_PILOT_MODELS=فیدلیتی پرایم
PUBLIC_PILOT_CAR_LIMIT=1
PUBLIC_PILOT_AD_LIMIT=8
MAX_DETAIL_PAGES_PER_SOURCE=2
```

**قرار دادن مقدار ۱ در PUBLIC_ACCESS_APPROVED اعلام تأیید سیاست دسترسی توسط بهره‌بردار است؛ برنامه نمی‌تواند خود مجوز قانونی را صادر کند.** اگر مجوز یا امکان دریافت روشن نیست، آن را تنظیم نکنید و به‌جای آن از فید/API مجاز (`SOURCE_BAMA_API_URL`) استفاده کنید. حالت پیش‌فرض همه منابع `feed` است.

ابتدا دیوار و همراه مکانیک را در پنل ادمین غیرفعال نگه دارید، باما را فقط پس از تأیید مجوز فعال کنید و درخواست بروزرسانی دستی بزنید. از لاگ Worker و پنل مدیریت، `fetched_count`، `valid_count`، `last_error_code` و لینک آگهی‌ها را کنترل کنید. نداشتن نتیجه ممکن است ناشی از تغییر ساختار صفحه، داده ناکافی، محدودیت سایت، یا رد محافظه‌کارانه آگهی‌ها باشد؛ به معنی تأیید استخراج نیست.

## افزودن دیوار و همراه مکانیک پس از نتیجه باما

پس از بررسی سیاست و مجوز همان سایت، متغیرهای مستقل وجود دارند:

```env
SOURCE_DIVAR_MODE=legacy_public
SOURCE_DIVAR_PUBLIC_ACCESS_APPROVED=1
SOURCE_HAMRAH_MODE=legacy_public
SOURCE_HAMRAH_PUBLIC_ACCESS_APPROVED=1
```

این مقادیر **نباید بدون مجوز/بررسی شرایط منبع فعال شوند**. برای دیوار، مسیر رسمی کناردیوار در اولویت است. اگر مجوز مرورگری صادر نشده، همان فید/API مستقل قبلی را به کار ببرید و `SOURCE_*_MODE=feed` بماند.

## ساخت و استقرار
Worker جدید از تصویر رسمی Playwright v1.57.0 و مرورگر Chromium سازگار استفاده می‌کند. تنها Dockerfile سرویس Worker تغییر کرده است:
`v30/Dockerfile.worker`، و فایل وابستگی `v30/requirements.worker.txt`.
برای ZIP با Dockerfile در ریشه، فایل‌های پوشه `v30/` را در ریشه آرشیو قرار دهید و Dockerfile.worker را به Dockerfile تغییر نام دهید. این ZIP باید روی **davoodicar-worker** مستقر شود؛ سرویس Web همچنان از Dockerfile معمولی استفاده می‌کند. `DATABASE_URL` را فقط به‌عنوان متغیر محرمانه در Liara وارد کنید.

**تست پذیرش واقعی:** حداقل یک دریافت موفق بدون کپچا/۴۰۳، چند آگهی با URL قابل ردیابی و قیمت درست، تکرار اجرای ساعتی، حداقل ۵ آگهی هم‌گروه برای ساخت بازه. داده موجود قبلی در صورت شکست حذف نمی‌شود.

این نسخه یک **پایلوت اتصال مشروط** است، نه تضمین دریافت قیمت زنده. در صورت نامجاز بودن/مسدودشدن، منبع باید غیرفعال بماند.
