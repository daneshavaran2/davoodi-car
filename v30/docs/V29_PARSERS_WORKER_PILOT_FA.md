# داودی‌کار ۳۰.۶ — استخراج آزمایشی مستقیم آگهی‌های عمومی

در نسخهٔ جدید، کانکتورهای نسخهٔ ۲۹ باما، دیوار و همراه مکانیک به Worker نسخهٔ ۳۰ متصل هستند و برای **صفحات عمومی**، دیگر به تنظیم URL فید اختصاصی یا `SOURCE_*_PUBLIC_ACCESS_APPROVED` احتیاج ندارند. فرانت‌اند و API جست‌وجو تغییر نمی‌کنند؛ فقط Worker در پس‌زمینه با محدودیت تعداد مدل و آگهی اطلاعات تازه را دریافت می‌کند.

**توجه:** موفقیت دریافت آگهی در Liara هنوز تأیید نشده است. برای این سه سایت هنوز امکان مواجهه با CAPTCHA، HTTP 403/429، تغییر DOM، صفحات JS، یا فقدان آگهی دارای مشخصات کامل وجود دارد. در این حالت خطا ثبت می‌شود و قیمت ساختگی ایجاد نمی‌شود. از کپچا، ورود اجباری یا محدودیت دسترسی عبور نمی‌کنیم.

## راه‌اندازی روی davoodicar-worker

فقط ZIP اختصاصی Worker را روی سرویس `davoodicar-worker` منتشر کنید؛ Web و PostgreSQL تغییری نمی‌خواهند. همان `DATABASE_URL` قبلی را در Worker حفظ کنید.

متغیرهای پیشنهادی Worker:

```env
SERVICE_ROLE=worker
SCHEDULER_TZ=Asia/Tehran
PORT=8000
MARKET_FETCH_MODE=playwright
PUBLIC_PILOT_MODELS=فیدلیتی پرایم,سانتافه
PUBLIC_PILOT_CAR_LIMIT=2
PUBLIC_PILOT_AD_LIMIT=8
MAX_DETAIL_PAGES_PER_SOURCE=4
```

اگر `SOURCE_BAMA_API_URL` یا سایر فیدهای معتبر را قبلاً تعریف کرده‌اید، اولویت با همان فید است. اگر URL فید تعریف نشده باشد، برای باما، دیوار و همراه مکانیک حالت پیش‌فرض `legacy_public` می‌شود. می‌توانید با `SOURCE_BAMA_MODE=feed` هر منبع را به حالت فید قبلی برگردانید. متغیرهای `SOURCE_*_PUBLIC_ACCESS_APPROVED` دیگر استفاده نمی‌شوند.

## مراحل اجرای آزمایشی

۱. در مدیریت منابع فقط **باما** را فعال و بقیه را فعلاً غیرفعال کنید. با این کار، پیش از اضافه‌کردن دیوار و همراه مکانیک، نتیجهٔ باما روشن می‌شود.

۲. «درخواست به‌روزرسانی دستی» را بزنید. حدود یک اجرای Worker بعد، `fetch_runs` برای باما را بررسی کنید: `fetched_count` و `valid_count` و `last_error_code`. این آمار تنها بعد از اجرای واقعی معنی دارد.

۳. اگر تعداد معتبر صفر بود، نوع خطا را ببینید: `NO_VERIFIED_LISTINGS` یعنی صفحات خوانده شده‌اند ولی داده‌های دقیق لازم (سال/تیپ/کارکرد/قیمت/گیربکس) تأیید نشده‌اند؛ `PARSER_CHANGED` یعنی ساختار صفحه با کد هماهنگ نیست؛ `HTTP_403` / `HTTP_429` / `CAPTCHA_OR_CHALLENGE` یعنی درخواست محدود یا رد شده است.

۴. در صورت موفقیت باما، دیوار و سپس همراه مکانیک را فعال کنید و نمونه‌گیری را با آگهی‌های قابل بازکردن بررسی کنید.

۵. حتی اگر چند آگهی دریافت شوند، «بازه قیمت» فقط پس از داشتن دست‌کم **پنج آگهی مشابه و هم‌گروه** ساخته می‌شود. گروه‌ها بر اساس مدل، سال، تیپ، وضعیت صفر/کارکرده، کارکرد و بدنه جدا هستند.

### اگر مرورگر روی سرور خطا داد

`MARKET_FETCH_MODE=http` را برای آزمون HTML عمومی به‌جای Chromium تنظیم کنید. این حالت فقط در صورت موجودبودن آگهی در HTML صفحه نتیجه می‌دهد؛ پشتیبانی JavaScript را از دست می‌دهد. هیچ راهکاری برای دورزدن محدودیت دسترسی انجام نمی‌شود.

### وضعیت تحویل

تغییرات کد و تست‌های آفلاین در GitHub ثبت شده‌اند. قالب لینک و آگهی عمومی باما با نمونه صفحه‌های عمومی بررسی شده است، ولی **تست واقعی Worker با دسترسی شبکه از داخل Liara** و ثبت آگهی در PostgreSQL باید بعد از انتشار انجام شود. API رسمی یا مالکیت دادهٔ سایت‌های ثالث ادعا نمی‌شود.
