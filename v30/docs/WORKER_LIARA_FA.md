# ورکر مستقل داودی‌کار — نسخه ۳۰.۲ برای Liara

**این فایل را در برنامه اصلی `davoodicar` منتشر نکنید.** یک اپلیکیشن جدید در همان تیم/شبکه با نام پیشنهادی `davoodicar-worker` و پلتفرم Docker بسازید و ZIP را در آن منتشر کنید. فایل `Dockerfile` در ریشه ZIP قرار دارد؛ ساختار داخل ZIP را هنگام انتشار به همان شکل حفظ کنید.

## تنظیمات برنامه Worker

در بخش Environment سرویس جدید، **DATABASE_URL را با آدرس خصوصیِ PostgreSQL که در سرویس Web استفاده شده یکسان بگذارید**. آدرس/رمز را در GitHub یا فایل `.env` منتشر نکنید. متغیرهای غیرمحرمانه:

```env
SERVICE_ROLE=worker
SCHEDULER_TZ=Asia/Tehran
PORT=8000
DB_WAIT_INTERVAL=3
MAX_PAGES_PER_SOURCE=8
```

در این بسته Worker مستقل در هر اجرای برنامه با دیتابیس ارتباط برقرار کرده و سپس در یک حلقه دائمی هر ساعت در ابتدای ساعت محلی تهران اجرا می‌شود. لاک advisory در PostgreSQL برای جلوگیری از هم‌پوشانی اجراها استفاده می‌شود. **نیازی به باز بودن مرورگر یا صفحه سایت توسط کاربر نیست**.

### بررسی نتیجه پس از انتشار

- `/api/live`: HTTP 200 به معنای روشن‌بودن فرایند و سرور سلامت Worker است، **نه** تأیید استخراج موفق قیمت.
- `/api/worker/health`: اگر دیتابیس آماده باشد HTTP 200 برمی‌گرداند و `enabled_source_count` و `last_scheduler_run` را نشان می‌دهد. اگر دیتابیس وصل نباشد، JSON با HTTP 503 دریافت می‌کنید.
- لاگ Worker باید شامل `WORKER_DB_BOOTSTRAP_OK` و `WORKER_LOOP_STARTED` باشد. پیام‌های `Scheduled collection` یا `Manual collection` نتیجه واقعی چرخه‌ها را نشان می‌دهند.
- می‌توانید وضعیت دقیق هر منبع را از بخش ادمین اپ **Web** با `GET /api/v1/sources/status` و توکن مدیریت دریافت کنید.

### مهم: آگهی‌های واقعی تا اتصال منبع وارد نمی‌شوند

شش منبع در پایگاه داده **پیش‌فرض غیرفعال‌اند**. برای فعال‌سازی هر سایت، ابتدا یک فید JSON قانونی و قابل اتکا تهیه کنید، سپس `SOURCE_<NAME>_API_URL` و در صورت نیاز `SOURCE_<NAME>_API_TOKEN` را در Environment همین Worker تنظیم کنید و منبع را از پنل/API مدیریت وب فعال کنید. فقط واردکردن نام سایت به معنای استخراج واقعی نیست. Worker برای دورزدن محدودیت‌های سایت‌ها از Playwright یا CAPTCHA bypass استفاده نمی‌کند.

### نکات Liara

- برنامه `davoodicar-worker` را در **همان تیم و شبکه خصوصی** PostgreSQL و Web ایجاد کنید؛ hostname دیتابیس خصوصی خارج از این شبکه کار نمی‌کند.
- اپ Worker جدا از وب اپ است؛ نباید `SERVICE_ROLE=worker` را در تنظیمات برنامه اصلی `davoodicar` قرار دهید، چون در آن صورت سایت کاربر از دسترس خارج می‌شود.
- با توجه به نیاز احتمالی Liara به پورت HTTP در اپ Docker، این بسته یک سرور سلامت سبک روی `$PORT` اجرا می‌کند. این سرور قیمت یا API مدیریت ارائه نمی‌کند؛ Worker همچنان پردازش اصلی پس‌زمینه است.
- از آنجا که اعتبارنامه‌های PostgreSQL و Liara قبلاً در گفتگو/تصویر نمایان شده‌اند، **آن‌ها را تعویض** و فقط در Environment وارد کنید.
- در صورت قطع دیتابیس، وب‌سرور سلامت با وضعیت `waiting_for_database` فعال می‌ماند و اتصال مجدداً تلاش می‌شود؛ این به معنی موفقیت اتصال نیست.

**وضعیت:** کد و ساختار به‌صورت محلی آماده و تست شده است؛ استقرار واقعی روی حساب Liara و موفقیت منبع زنده در این گفتگو تأیید نشده‌اند.
